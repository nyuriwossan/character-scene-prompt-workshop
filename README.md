# キャラ挿絵プロンプト工房

ひとりのオリジナルキャラクターを軸に、物語の一場面を画像生成AI向けの英語プロンプトに組み立てる無料の静的Webアプリです。初回は、銀髪の人物が温室で振り返るサンプルを開きます。キャラクター名は空欄で、名前を入れる前からプロンプトを作れます。

[公開版の編集室を開く](https://nyuriwossan.github.io/character-scene-prompt-workshop/)

## v1.1での場面づくり

背景は「現代日本」から「学校・青春」「街並み・交通」「デート・お出かけ」「住居・日常」「仕事・公共施設」「季節・行事」を選び、場所を指定します。59件の新しい場所と、「その他の背景」にある従来の7件を利用できます。たとえば「放課後の教室」を選んで、照明を「輪郭を照らす光」にすれば、同じ教室の光だけを変えられます。時間帯や季節に関係する一部の背景では、設定の組み合わせを確認するメッセージが出ます。

表情は8カテゴリ・39件です。驚きと照れを拡充し、困惑といじける表情を追加しました。視線は別の欄で選べます。「すべて」では日本語名・英語タグで検索でき、12件ずつ候補を表示します。カテゴリを閲覧しても現在の選択は保持されます。「指定なし」でその値を外せます。シーンを呼び出すと、保存した背景・表情のカテゴリが自動で開きます。

撮影距離「胸上」の自動生成語は、タグなら `upper body shot`、自然文なら `an upper-body portrait` です。旧版のJSONでも内部ID `bust` からこの表現を生成します。保存形式は引き続きバージョン1で、登録済みの名前、直接入力、LoRAを含む自由文はそのまま読み込みます。PixAIアプリによる受理や実際の描画結果は未検証です。

## 最初の一枚

1. 「キャラクター素体」で名前・メモ・外見を設定します。手持ちのタグや英文は「直接入力」へ貼り付けます。素体・衣装・画風をひとまとめにした文章は「既存プロンプトを一括入力」を開き、採用にチェックを入れます。
2. 衣装と画風を整え、「キャラを保存」でライブラリに登録します。「衣装差分」では現在の衣装を名前付きで登録・着用できます。差分を追加したらキャラクターも保存すると、あとでその組み合わせを呼び出せます。
3. 「場面プリセット」から12の場面を選びます。変更前後を確認して「適用する」を押し、表情・動作・カメラ・背景を調整してください。固定したシーン項目は適用対象から外れます。
4. 「プロンプト出力」で形式を選び、「全文をコピー」して画像生成サービスへ貼り付けます。「セクション別」では個別コピーができます。
5. 「シーンを保存」で一枚分の設定を記録します。「次の挿絵を作る」はキャラクターと固定中のシーン項目を維持して次の場面に進みます。

画像は工房用のオリジナル見本です。編集内容はプロンプトのプレビューに即時反映されます。画像生成サービスへの接続や画像生成処理はありません。素材を含めアプリに必要なファイルは同じサイトから配信します。

## 編集と保存

各パネルの開閉、入力モード、固定状態は別の値です。「使用しない」やプリセット適用後にも直接入力の原文は残ります。キャラクター名・メモは管理用で、英語プロンプトに混入しません。日本語の自由入力も原文のままです。一括入力を使うときは重複候補が表示されるので、必要に応じて個別項目を除外してください。

* **キャラクター保存**は素体・基本衣装・衣装差分・画風・一括入力を記録します。呼び出すと現在のシーン演出を引き継ぎます。
* **シーン保存**は、その時点のキャラクターを含む一場面全体を記録します。保存のたびに新しい記録を追加します。名前の同じ別バージョンも保存できます。ライブラリで呼び出し・複製ができます。
* **マイプリセット**は表情・ポーズ・カメラ・背景のうち、プリセットモードで編集した項目を登録します。直接入力まで残す場合はシーン保存を使います。
* **リセット**には項目・シーン・全入力の3種類があります。シーン・全入力は範囲の確認後に実行します。すべてのリセットに取り消しがあり、編集室末尾の「元に戻す」でも直前の対象操作に戻せます。保存済み記録は保持します。
* **保存先**はブラウザのオリジン別 localStorage です。公開先やブラウザが変わると保存先も変わります。移行やバックアップには「データ管理」のJSON書き出し／読み込みを使います。取り込み前に全レコードを検証し、置き換え前に件数を表示します。
* **破損・容量不足**は画面内に表示します。破損時は自動保存を止め、元データの退避と復旧を選べます。容量不足では編集中の内容をメモリに維持し、JSONへ書き出せます。

## カメラと出力

撮影距離・アングルはオリジナルの模式図から選びます。撮影方向・視点・画面内の配置・対象を独立して調整できます。主人公の手だけを映す演出にも対応します。顔アップと足元の動作、目を閉じる視線と驚きの表情、主人公視点と主人公の正面像などは、設定を維持したまま警告します。自由文の意味の自動解析は行いません。

カメラと背景で構造化されたアングルが重なる場合はカメラを優先します。同一の自動生成タグは一度だけ出力します。貼り付け文章とLoRA構文には正規化・翻訳・自動重み付けを行いません。

| 出力形式 | 表現 |
| --- | --- |
| 汎用英語タグ | カテゴリー順のカンマ区切りタグ |
| 英語自然文 | 選択した特徴から英語の文を組み立てる |
| PixAI SDXL系 | 単独人物のタグと、撮影条件を示す短い英語タグ |
| PixAI Tsubaki系 | 人物・カメラ・動作の関係を記す英語の段落 |
| NovelAI向け | 人物数タグと動作を前に置いたタグ列。入力済み強調構文は保持 |
| Markdown構造形式 | 見出し単位で英語プロンプトを整理 |
| 日本語設定一覧 | 日本語ラベルと直接入力の原文を併記 |

出力例は [EXAMPLES.md](./EXAMPLES.md) に収録しています。検証対象は設定の保持、出力文字列、画面操作です。各モデルでの画像品質・外見再現性は実生成で評価していません。

## 起動とGitHub Pages

Node.js 22以上とPython 3を使う開発手順です。アプリ本体はビルド・外部API・ログイン・依存パッケージを必要としません。

~~~sh
python3 -m http.server 8000 --directory dist
~~~

ブラウザで http://localhost:8000/ を開きます。ESモジュールを使うので、展開したHTMLはHTTP経由で開いてください。

このリポジトリは、GitHub Pagesの「Deploy from a branch」で `gh-pages` の `/ (root)` を配信します。`main` へのpushで「Publish workshop to GitHub Pages」がテストとZIP生成を行い、配信用ファイルを `gh-pages` に反映します。続いて公開ブランチ上の「Deploy workshop release」が実行され、公開結果を確認できます。

別の新規リポジトリに移す場合は、最初に `main` にソース一式をコミットし、`dist/` の内容と `.github/workflows/deploy-release.yml` を同じ構成で配信用の `gh-pages` ブランチに配置します。配信ワークフローを変更するときは、両方のブランチで同じ版に更新してください。Settings → Pages で `gh-pages` のルートを選び、Actionsから「Publish workshop to GitHub Pages」を実行してください。アセットは相対パスで読み込みます。

## テスト

~~~sh
npm ci --ignore-scripts
npm test
npm run examples
python3 scripts/package-source.py
~~~

単体テストにはNode.js標準のテストランナーを使います。UI操作の統合テストは開発用依存のjsdomで、実際のHTMLとイベントハンドラーを通して検証します。出力エンジン、保存・復元、リセット対象、警告、全プリセットの値、異常JSON・容量不足、GitHub Pages相当のサブパスを検証します。コード変更後は npm run --silent examples > EXAMPLES.md で出力例を更新できます。

ブラウザ検証は配信先の `checks/` を開き「検証を開始」を押します。390px幅・1280px幅のフレーム内で、背景・表情のカテゴリ選択と検索、7パネルの操作、保存・呼び出し、確認・キャンセル・取り消し、コピー対象、JSON読込、横スクロールを検証します。検証画面内の保存先とクリップボードはテスト用のメモリに分離しています。OSのクリップボードとの連携は編集室のコピーボタンで確認できます。

## データ構造と拡張

* `dist/catalog.mjs` に7セクションの選択肢（安定したID、日本語名、英語タグ、自然文）と場面プリセットを定義しています。場面を増やすには既存のフィールドIDの組み合わせとサムネイルを追加します。
* 背景と表情のカテゴリ、候補、背景固有の警告は `dist/scene-options.mjs` にあります。各候補は固有ID・日本語名・英語タグ・自然文の句を持ち、カテゴリと小分類は表示用です。
* `dist/engine.mjs` に生成、矛盾警告、スナップショット、保存検証を集約しています。形式を増やす場合はカタログの formats と generate に追加し、直接入力保持を含むテストを加えます。
* `dist/app.mjs` が操作・確認ダイアログ・表示を管理し、`dist/style.css` がスマホ幅、フォーカス、セーフエリアに対応します。
* JSONのルートは `schemaVersion: 1, draft, characters, scenes, customPresets` です。各セクションの `mode, values, raw, extra, open, locked` を独立して保持します。将来は decode の入口にバージョン移行を加え、移行後に現行スキーマを検証します。未知のバージョンは既存データを上書きせずエラーを表示します。
* `scripts/package-source.py` は配信用README、出力例、ソース一式のZIPをdistに生成します。ZIPにはそのZIP自身やサイト固有のホスティング情報を含めません。
